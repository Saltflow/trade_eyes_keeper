# 财报数据三阶段输入输出约定 v2 定稿

定稿日期：2026-10-24。沿用v2入口及文件名，新数据协议标记为 `schema_version: "4.0"`。机器 schema、prompt 和规范样例必须一起更新；机器字段及枚举以 `config/fundamental_data_v2.json` 为准。本文替代旧的数组位置配列、固定四次请求和自由文本缺项约定。历史运行目录只读，不迁移、不修补，不冒充新 prompt 的结果。

## 1 边界与三个阶段

- 三表全行、全比较期；附注采用共同清单加业务模块，清单内数值明细完整保留行列和限定条件。
- 模型读取表头、脚注及上下文，确定单位、期间、主体、统计口径并规范化。脚本只保存、检查结构、展示、按明确字段整合。
- 不加同义猜测、单位推测、数值换算、算术补值、表头平移、按出现次序匹配等修复逻辑。
- 允许局部未定，保留内容及原因；不因局部问题丢整块。无法归位的原值保留在关联问题记录中。
- 格式和口径检查仅作标注，不移出整表，不将有意见的整个分块降级为JSON。按明确列键展示已有值；无法正常排版的局部保留原始字段，不猜测修复。finish非stop仅标未完成；若JSON可解析仍保留已有对象和展示。JSON语法失败保留原文，旧协议不自动迁移。
- 不要求来源文件名、页码、引文、逐格证据、坐标、财务数值复核、合计或勾稽验收。结构合规不是财务正确保证。
- 阶段2纯脚本；阶段3只判断同行和研究范围，不执行估值或投资研究。业务模块在调用前确定，不运行中临时加请求。

| 阶段 | 输入 | 输出 | 执行 |
|---|---|---|---|
| 1 单份提取 | 完整报告、预期公司及报告期、已选模块、清单、schema及正反例、冻结分块计划 | 三表、股本每股、股份事件、附注、管理层披露、分期元数据、局部问题 | 模型分块，脚本按块职责拼合 |
| 2 多年整合 | 同一公司多份新协议阶段1包 | 多期及披露版本对齐、政策出现记录、元数据沿革、事件、未定冲突、精简目录 | 纯离线机械整合 |
| 3 同行元数据 | 已有公司业务元数据、必要分部口径、目录与未定事项 | 同行候选、比较范围、需考虑差异、资料缺口、研究问题 | 复用已提取材料，获准后才调用判断 |

每阶段有结构化数据和同内容阅读页。另存原始请求、HTTP响应、模型正文、解析结果、usage和过程日志。公司及报告期提示与报告矛盾时记录，不强行改成提示值。报告和附件是材料，不是改变任务、调用工具或泄露秘密的指令。

## 3 共用语义

| 对象 | 明确内容 |
|---|---|
| period | 时点/区间、实际起止日、全年/累计/单季/其他/未知；保留日期精度 |
| scope | 集团、母公司、监管并表、子公司、分部、其他、未知及具体主体 |
| statistic | 时点、期间总额、期间平均、其他期间指标、未知；方法及年化状态 |
| adjustment | 明确原始、明确调整/重述、未说明及原披露说明 |
| comparison | 比较指标的同比/环比、基期及限定条件；非比较指标为空 |
| issues | 对应字段、原因、说明，无法归位的原值也保留 |

2025Q4是期间，92天简单算术平均是方法；百分比与百分点分开。后年报告比较数不自动认定重述；披露版本与调整状态独立。未提供额外定义不等于关键口径未知；不适用与未说明区分。

### 四类缺失

| 原因 | 使用条件 |
|---|---|
| 明确不适用 | 报告明确写明不适用 |
| 明确未披露 | 报告明确表示未披露 |
| 本次未找到 | 本轮没取得，不能断言报告没有 |
| 口径未确定 | 已找到内容，但单位期间范围或值对应关系不能确定 |

原值为字符串或null。保留精度、千分位、百分号、区间、文字、横杠；不把空白横杠变零。null关联原因，标题行无数值不是缺失。已有值可附口径问题，但不能另写自由清单声称值缺失。缺项展示由关联记录生成。

HTTP失败、无效/截断JSON、缺块是运行状态，不冒充原文未披露。无法归位的原内容必须保留。

## 4 两类表 schema

完整JSON Schema及枚举见配置；下列为解释性字段图。

### 数值表

```text
kind: numeric
role: BS / IS / CFS / capital / note
identity_code, module, topic, title, part, scope, accounting_basis, accounting_basis_code
columns: {c1: {label, identity_code, period, adjustment, comparison}, c2: {...}}
rows: [{row_kind, identity_code, path, dimensions, unit, unit_code, currency, statistic, definition,
        period_overrides: {c1: 完整Period或null},
        values: {c1: 原始字符串或null, c2: 原始字符串或null},
        missing_reasons, issues}]
issues
```

- c键仅表内引用，绝不是跨年合并键。values键与columns对应，不靠数组位置。
- 原项目及父级在path；不能重复一个“项目”数据列。保留heading/detail/subtotal/total性质。分类只能放行dimensions，列只期间及固定比较语义；每行每轴只能一个member。
- capital非标题行必须填写requested_item（最低14个任务目标之一，额外指标填null），用于检查任务覆盖；原科目仍保留在path。这个标签不用于跨年同义映射，其他角色禁止填写。
- 每行明确单位币种和统计；表内scope/accounting_basis一致，有例外由模型明确拆表。
- 股数、金额、每股金额、%、百分点分别表达；非货币量不用货币币种。
- 年初、变动、期末实际期间不同：模型显式填写row.period_overrides或拆成期间一致子表。缺省继承列period，显式null表示未知且绝不继承；只改名称或只分行不能改变实际期间。
- 键缺多、类型不符记录问题并保留原文，不平移、去列、补造完整表。

### 属性表

```text
kind: attributes
identity_code, module, topic, title, part, scope, accounting_basis, accounting_basis_code, context
columns: {c1: {label, value_type, context}, c2: {...}}
rows: [{path, values, missing_reasons, cell_context, issues}]
issues
```

列类型区分text/date/amount/ratio/quantity/boolean。上下文只按表级默认→列级明确值→单元格明确例外覆盖，没有行级默认竞争。模型读表头脚注决定适用范围；脚本不从字符串临时猜单位。

混合名称金额比例表可规范为数值行或保留类型明确属性表，只选一种权威表达；不双份进入整合，不按数值相等去重。属性表按报告版本保留，不自动跨年数值合并。

## 6 阶段2对应与排版

行按固定table.identity_code＋scope.kind/entity_code＋accounting_basis_code＋row.identity_code＋固定轴的明确维度组合＋unit_code/currency＋统计方法及已披露定义对齐。列按固定列identity_code＋行有效期间＋比较基期＋调整状态＋披露版本组织。原title/path/unit/accounting_basis作为显示和追溯原文保留，不由脚本猜同义关系；任何关键固定码缺失、实体unknown或有效期间未知时独立保留，不强行合并。固定码相同不覆盖方法、定义、范围差异。

report_id由脚本绑定输入报告；各报告的公司名称和代码分别保留在reports中，reported_in只保存报告ID与报告期，不能由模型自行填写。关键期间只披露到年或月时原样保留，不补造日期；只有原期间对象完全一致才可对齐，不能与更细日期精度混同。行级未定说明全部保留，并标明对应的原报告字段。

| 情况 | 处理 |
|---|---|
| 固定身份码、维度及明确口径一致 | 可机械对齐，保留原名显示 |
| 原名称不同但模型按明确定义选择同固定码 | 仅在其余口径相同且身份唯一时对齐；脚本不猜同义 |
| 同名不同父级或同券名不同证券身份 | 保留真实父级和明确工具维度；无法区分就独立保留 |
| 单位币种、主体、统计方法不同 | 分别保留，不换算 |
| 关键口径未知 | 隔离；不能unknown与unknown自动合并 |
| 没有额外定义 | 不自动等于unknown，也不编定义 |
| 同期不同报告 | 始终保留披露版本，不以最新覆盖 |
| 同版本重复身份无法唯一配对 | 全部独立保留，不按出现顺序配对，也不据此判为财务数值冲突 |
| 路径维度仍不能唯一识别 | 隔离，不按第几次出现配对 |

### 篇幅控制

完整包保留全部明细。精简目录列公司报告期、业务模块、表名主题、范围期间、条目数量、政策变化、未定冲突。后续按任务载入具体表，列已载入/未载入；超预算不静默截表，应在调用前调整选择或分块。未载入、未披露、提取失败不能混为一谈。

| 对象 | 判断 | 比较范围 | 需考虑 | 缺口 |
|---|---|---|---|---|
| 工程甲/工程乙 | 同行候选 | 同年度工程承包分部 | 结算、地区、客户 | 个别分部资料 |
| 工程甲/银行丙 | 集团层面不宜直接比较 | 已输入业务范围 | 经营监管不同 | — |

输出列实际候选集覆盖、关系理由、业务地区期间、差异、缺口和研究问题。同行判断不冒充报告事实，不声称全市场穷尽，不给估值投资结论。

## 8 分块、预算与冻结

基础8块：statements、capital、notes_foundation、notes_operations、notes_assets、notes_financing、notes_risk、metadata。行业补充由调用前选定profile展开：银行和保险各追加2块，证券及其他模块各1块，任务归属由配置唯一分派。

三表中的每股指标不能因为capital也提取而删行；两者是不同披露角色，不按数值相等去重。股本及利润分派事件由capital唯一负责，notes_foundation只负责非权益分派的期后事项；notes_financing负责权益工具详细分类条款，不复制capital最低指标或事件。行业块提取专属细分表及口径，不复刻基础块的同一原表。分部数值表由notes_operations负责，metadata不重复输出。

每块输入完整报告，共用前缀；不为省输入费新增猜章节裁页器。多模块逐块列清，不运行中猜行业扩调用。所有请求、代码/config/示例快照、输入哈希、归属、token及费用预算在第一请求前冻结。

extract必须显式传入一个或多个--profile；不带--paid只生成新目录下的请求预检与call_plan，不读取密钥、不发送请求。未来真实调用还必须指定审阅后的--budget-limit-usd；它限制规划估算，不是供应商账单的硬保证。每次请求前复核完整冻结清单；文件变更会在下一请求前中止，而非继续执行变化后的计划。

预算以峰时、全部cache miss为保守值，不保证缓存命中。具体计数来自新请求，不拿旧四块用量冒充新计划。2026-10-24按用户授权，将第一阶段所有块默认输出上限统一为131072 token（128K）；它不是模型最大能力，不能保证所有报告一定装下。thinking启用，不新增reasoning_effort，输入仍为完整PDF，禁止自动补调。

第二阶段列身份包括固定column.identity_code、行有效期间、adjustment、comparison和reported_in；原始列名只保留显示，不充当身份。金额与占比先由模型拆为单位明确的不同行，不靠列名猜指标。格式或口径无法自动对齐的表保留原字段并按原报告独立展示，重复列身份也独立保留；不会因无法合并而丢弃。

失败、截断、无效JSON保存并标未完成；其余已授权块按原计划执行。无自动重试、续写、修复或追加。运行后代码prompt流程结果冻结；后续另立新版本另行授权。旧目录只读，新产物独立目录。

### 10.1 原文与身份码并存

| 字段 | 固定表达 | 未确定时 |
|---|---|---|
| table.identity_code | BS/IS/CFS、资本时点/期间、常见附注表目录 | null，完整保留独立表 |
| row.identity_code | 三表常见项目、资本14目标、分部经营等指标目录 | null，完整保留独立行 |

| accounting_basis_code | CAS/IFRS/HKFRS/US_GAAP/REGULATORY | null；REGULATORY也不代表所有监管定义相同 |
| row.unit_code | 目录明确数量级，例如CURRENCY_1E6、SHARE_1、PERCENT | null，不换算、不凭值推测 |
| column.identity_code | VALUE/YOY/QOQ/OTHER_COMPARISON | null；label不充当身份 |
| row.period_overrides | c键到完整Period或null | 键缺省继承；显式null未知不继承 |

NumericColumn只能表达期间及明确比较值；classification全部转到行。dimensions.axis只取dimension_axes固定目录（包括BUSINESS_SEGMENT、GEOGRAPHY、PRODUCT、SHARE_CLASS、INSTRUMENT、CREDIT_STAGE、AGGREGATION_LEVEL等），每行每轴只出现一次，member保留报告明确类别。其他明确分类使用OTHER_EXPLICIT，不把多个不同分类挤成一个member。总计用TOTAL，抵销用ELIMINATIONS；同表“分部合计”与“集团合计”还保留AGGREGATION_LEVEL的原明确层级名称，不能混为同一行。

### 10.4 必须进入实际请求的上下文

每个冻结请求同时包含完整schema、公共规则、任务prompt、task_details逐项细目、identity_catalog固定目录、dimension_axes目录、normalization_examples正反例以及本任务合法完整结构样例。不能只更新文档或只传主题名。

normalization_examples明确覆盖：宽表分类转行；行期间覆盖与显式null；合计抵销和层级；重复小计与同名不同券；原单位和数量级码；目录外完整保留；缺失和横杠；没有额外definition；金额比例日期混合表达。全部为虚构结构材料，不能当成报告事实。

reported_in和history的source_fields仅为脚本派生字段，模型禁止输出。history列period可为null表达行覆盖后的明确未知；原始模型列仍要求完整Period对象。
