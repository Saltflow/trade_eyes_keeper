# 触发数据每天三次独立采集（2026-11-03）

用户要求降低原有30秒价格取数频率，每天3次足够。配置为
`scheduler.data_collection_times: ['09:50', '14:30', '19:00']`，时区沿用
`scheduler.timezone`，当前为 Asia/Shanghai。此设置独立于日报、启动报告和简报的开关。

管理触发器仅在这些时段按活动条件的真实依赖采集免费报价、历史/估值或公告。
慢源完成后、修改触发器后和非采集时段重启时，只重算已有事实，不额外访问来源。
定时/日期到期判断继续使用独立时钟队列。30秒的本地时钟唤醒不再等于30秒取行情。
同一日同一时段由执行库持久请求键去重，重启不会重复采集；时段延迟10分钟以上
不额外补跑，也不追补离线期间的全部历史时段。没有活动数据依赖时不会制造空采集。

个人监控模块本来就复用09:50、14:30、19:00三个时段，并且不依赖报告enabled开关；
本次不改动其业务状态、重试及投递。手动或实际触发的报告仍可按需取数，不计作
后台定时采集任务。盘中短暂越过阈值可能在两次采样之间遗漏；报价新鲜度及市场
开闭市规则保持原合同，不能将19:00取得的陈旧收盘报价伪装成盘中实时价格。

未配置`data_collection_times`的旧隔离配置保留原有间隔模式。仓库本机配置及生产
配置需要显式设置三个时段；仅改本机YAML不能宣称生产已生效。心跳会显示
`collection_mode`、`collection_times`、`collection_timezone`、`next_collection_at`。
