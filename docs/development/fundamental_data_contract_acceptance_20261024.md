# 财报数据协议定稿与离线验收记录

## 1 定稿对象和验收边界

- 语义约定：`docs/design/fundamental_data_contract_v2.md`。
- 机器schema、各块prompt、清单和分块定义：`config/fundamental_data_v2.json`。
- 规范例和反例：`tests/fixtures/fundamental_data_v2_contract/`，包含全部任务例子、两年完整规范响应及无效反例。
- 阶段1模型理解原表并规范输出；阶段2只按明确字段整合；阶段3复用元数据判断候选关系和研究范围。
- 不实现同义匹配、金额换算、表头平移、按第几次出现匹配科目或依据数字猜单位。未知关键口径隔离；没有额外定义不自动等于未知。
- 不加入来源页码、证据对象、财务准确性复核或勾稽。所有测试结论只针对数据结构、保存、展示、整合及调用边界。

新数值表使用c键columns及同键values、原始层级path、行unit/currency/statistic、列period/adjustment/comparison、表scope/accounting_basis。属性表按表→列→单元格上下文覆盖，没有行级默认歧义。
披露版本始终保留；平均/时点、累计/单季、币种单位、母公司/集团/监管范围不混合。同名不同父级不合并，不可唯一识别的重复路径隔离。

## 5 预算方法

本轮实际新增模型调用数为0，新增供应商模型token和费用均为0。公开网页查询不属于本项目模型调用。Codex会话用量、历史DeepSeek调用、未来预算分别记录。

设新请求离线估计输入合计为I，各块最大输出合计为O。保守峰时全cache miss预算：

```text
USD upper estimate = I × 0.30 / 1,000,000 + O × 1.20 / 1,000,000
```

这里的I是本地计数估计，存在服务端分词/图像计费差异；不是供应商已确认的精确账单。未来批准调用前需留出明确余量并固定规划费用限额；当前预检未指定限额，没有获得付费执行授权。预算不承诺缓存命中或非峰优惠，不依据旧调用缓存率折扣。

最大输出部分独立预算：基础8块USD0.265421；单一般profile9块USD0.304743；银行或保险10块USD0.344064。还必须加本次完整报告重复输入的预算，不能把这些数写成整次调用费用。

历史输入规模只用于解释完整PDF重复发送的成本：招行旧4块输入999157、输出22712；泸州旧4块输入520105。历史用量不等于新请求用量，不用当前费率重算后冒充当年实际扣费。新schema/prompt/示例会改变输入及输出长度。

### 6.4 仍存在的问题与接受边界

1. **新prompt尚未经过真实模型验收。** JSON模式不保证业务schema正确，也不能保证三表/清单内附注无漏行。离线通过不能写成模型效果通过。
2. **输出上限可能不足。** 三表或某附注块超过32768 tokens会以不完整结束，原文保存、不自动续写、修复或追加付费请求；必须先人工审阅再决定后续。
3. **旧结果不能直接使用新整合。** 旧缺少关键语义字段，不自动迁移；仍可看原目录阅读页和新回放的原文。以后需单独批准新提取。
4. **预算是本地token规划估算。** 服务端分词/图像计数可能不同，`--budget-limit-usd`约束规划估计，不是供应商账单硬保证；当前费用限额为空、未执行付费。
5. **未定口径和名称变化可能产生更多分行。** 这是明确保留差异的行为；脚本不靠同义、金额相等或出现序号消除它们。
6. **真实排版尚未截图验收。** 静态HTML检查通过，浏览器本地文件策略阻止了自动视觉检查。

未检查财务数值正确、勾稽或原文覆盖率；没有研究/估值开发、真实第三阶段判断或付费调用。本次数据链路离线通过不代表旧研究系统所有依赖已收敛，亦不代表实现“每脚本不超过100物理行”的历史全项目目标。
