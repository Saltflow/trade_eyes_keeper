# 跨股票实物分派账本（2026-10-31）

## 交付范围

本轮本地实现将官方声明、股份寄发、实际账户结算与授权估算分开保存。用户随后明确
“实际到账可以预估，税费按照港股通通行的来”，因此提供显式的港股通估算政策。
`CorporateAction`
携带结构化 `InKindDistributionTerms`，独立外部原始行情放在
`PriceHistoryBundle.external_prices`，缓存往返保留这些输入。

有完整因果证据的线性股份分派复用同一个日推进账本，接入现金档位、目标仓位、
批量评估、静态基准、首次买入对照及参考持仓。除权日按原有持仓捕获权益，母股
卖出不抹去已捕获权益；实际交付前不可交易，零股结算前不作为可用现金。
已确认的零股净额只入账一次，不重复扣费用或预扣税。报告与缓存保存外部权益、
交付费用/税、零股结算及处置现金流，以便与 NAV 对账。

真实凭据模式下，声明、来源哈希、资格/选举、费用、税、实际交付、零股净额及付款
日期缺失时，继续输出明确缺证诊断。估算模式使用独立的 `estimated_*`、政策 SHA
和假设清单；不会给 `actual_*` 或真实凭据哈希填造数据。前复权不能凭母股价格跳空
猜现金金额；Tencent 已匹配日期/成交量的真实 raw/qfq 双路可保留原信号序列，另记
内容哈希，执行权益仍独立解析和计算。参考账户错过除权日捕获、或捕获后条款变更，
要求明确对账，不用今天的持仓倒推历史资格。

无需创建美国 ADS 持仓；明确选择 ADS 时仍须遵守来源确认的 40 天限制。外部资产持有期间
又发生股息/拆股时，仍需下一层权益与结算合同，未解决时明确阻断。

## 明确提供结算证据

`scripts/import_in_kind_settlement.py` 是受控导入入口：必须显式给出
`--store-root`、`--code`、`--ex-date`、`--receipt` 与调用者已核实的
`--expected-sha256`。默认只预检，`--apply` 才对唯一匹配事件原子写入，并保留
按原始 SHA 命名的备份；行情、元数据和其他公司行为保持原字节。

回执为至多 64 KiB 的 UTF-8 JSON，`schema` 为 `in-kind-settlement-v1`，需匹配
`code`、`ex_date`、`asset_code`，并有明确 `source_url` 与 `terms`。只能更新资格、
选举、实际交付/发布时间、零股净额/付款/发布时间、单股费用/税和处置规则；不能
用结算回执改声明比例。调用者仍负责核实回执来源，哈希只证明指定字节未变。

估算事件默认拒绝直接导入实际回执。必须另加`--reconcile-estimated`明确转入真实
凭据对账：清除旧估算及其执行事实，仅依据本次实际证据验证。完整凭据才可执行；
部分凭据保持`confirmed`但`action_executable=false`，后续自动准备不得重新估算或
抓取公开声明覆盖该对账状态。无`--apply`仍只预检，错误日期/金额不写缓存。

旧缓存缺结构化声明时，可成组提供 `--declaration-json`、`--declaration-source`；
导入器核对原文哈希并重新解析官方声明，不直接信任 JSON 填写的比例。缺失事实
继续保留为缺证；导入不自动补造调整因子、改活动策略或解除全部数据门禁。
