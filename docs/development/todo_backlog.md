# Backlog

## P1 — 港股税后现金分红统一回测

**状态：** 已完成；全量验证与部署前门禁已通过，等待人工发布决定。

**目标：** 按账户层保守假设，在港股除权日对持仓现金分红计提 20% 税务成本；
策略、静态基准和参考持仓必须使用同一税后总回报口径。

### 实施边界

- 在统一市场输入中传递逐日逐标的 `cash_dividend_per_share`、除权日、币种和
  `published_at`；只有 `published_at <= ex_date` 的 action 可进入历史仿真。
- 统一 Backtester 以原始可交易价格和税后现金流计算 NAV：
  `net_dividend = shares × cash_per_share × (1 - withholding_rate)`。
- 将税率配置在执行/账户合同中，默认：`hk: 0.20`、`a_share: 0.00`、`us: 0.00`；
  不硬编码，也不把该假设表述为所有投资者的法定税率。
- 搜参、日报、今日扫描、静态等权基准、外部参考标的和 `ref_portfolio`
  全部复用同一 action/NAV 路径；禁止在通知或 DCF 模块二次扣税。
- 前复权/总回报序列与显式现金流二选一，禁止重复计入分红；回测报告输出
  税前分红、税务成本、税后分红和净收益影响。

### 验收

- 100 股、每股 HKD 1.00 分红的除权日，现金净增加 HKD 80，税务成本为 HKD 20；
  未持仓、除权日前卖出和除权日后买入均不计税。
- 与拆股、停牌、最小持有期、部分卖出、外汇换算和周/季末持仓快照一致。
- 同一含分红路径下，策略、静态基准和参考持仓的 NAV 一致；改变 `hk` 税率只改变
  税后现金流，不改变信号、成交价或 DCF 公允价值。
- action 缺少可信发布日期时 fail closed，不把事后 Yahoo action 用于历史窗口。

## P3 — 三市场标的池稳健性 benchmark

**状态：** 已实现；执行 `python main.py --universe-robustness` 后生成可审阅
JSON / CSV / HTML，不自动激活或改写任何监控配置。

**目标：** 在不修改监控配置、活动策略或生产策略指针的前提下，量化当前 A/HK/US
标的池对删减、扰动和横截面排序的敏感性，避免把单一配置池的偶然结果误判为可推广
策略。

### 实施边界

- 以每个市场当前完整、数据就绪的标的为基线；不从监控配置删除任何代码。数据未就绪的
  代码只在对应 benchmark 变体中明确记录排除原因。
- 复用 84 个月 raw 成交 / qfq 信号 / 公司行为、`22/16/2/4` 窗口、Solver、预算和评分
  公式，不创建另一套回测或评价合同。
- 至少产生基线、leave-one-out、确定性比例删减和横截面排序变体；每个市场单独执行，
  不得以 A 股结果替代 HK/US 结论。
- 对每个变体报告四个 Holdout 的等权收益、主基准超额、最差最大回撤、Sharpe、交易数、
  数据就绪覆盖和相对基线变化；产物必须版本化、可机读且提供完整 HTML 报告。
- 结果只能作为诊断与人工激活证据；不得自动切换 active pointer 或变更生产策略。

### 验收

- 同一输入和随机种子下，变体定义、入选/排除代码和汇总指标可复现。
- 每个市场均有基线和至少一种有效扰动；数据不足的市场输出 fail-closed 诊断而不伪造
  比较结果。
- 报告清楚区分 ranking、purged 与四个 holdout，且任何 holdout 不进入 Solver。
- 测试覆盖变体构造、市场隔离、数据就绪排除、Holdout 聚合、报告序列化和禁止自动激活。
