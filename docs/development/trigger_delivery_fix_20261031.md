# 触发报告飞书卡片与动作状态修复

2026-10-31，v1.21.1。

## 线上事实

用户创建的三季报触发器于北京时间 15:22 命中五个事件：600036 当天，以及
01339、002594、00956、00883 的次日。十个独立动作按原合同合并为一次简报和
一次日报，使用生产完整 23 个监控标的，行情无缺失。

简报于 15:23:36 结束失败；日报紧接着使用同一报告队列，于 15:26:23 结束失败。
两个飞书回执均为 HTTP 400。用户引用回复产生时日报仍在生成，不能据此推断
日报动作不存在。`hk:blocked` 属于已有策略分析就绪问题，与 HTTP 拒收分开处理。

配置提案 `9557134912bd` 在排查时仍为 pending，关闭三个固定报告任务的改动
没有执行。本次修复不确认提案、不改定时任务、触发规则、账户或策略指针。

## 根因和修复

原通用构建器返回飞书 JSON 2.0 卡片，正文位于 `body.elements`；触发投递适配器
却把触发提示写入顶层 `elements`，使卡片不符合结构。现深拷贝原卡片，在
`body.elements` 首项加入原因，保留原正文、表格和其他配置。发送前检查该层级，
错误格式在请求认证和投递之前失败。结构依据
[飞书 JSON 2.0 官方文档](https://open.feishu.cn/document/feishu-cards/card-json-v2-structure)。

HTTP 失败回执增加整数平台错误码及安全格式的日志 ID，不记录平台原始响应、
认证令牌、收件人或私有报告正文。历史回执只保存 HTTP 400，不能补造当时未记录
的平台错误正文。

查询界面按 action_index 分开显示简报、日报、提醒的最新状态，并只读核对已提交
run 的排队、生成、投递或终态。明确区分“发送失败”“结果不明”“已经送达但
报告部分数据未就绪”，不把另一动作的单条 last_result 当作全部动作的结果。

## 验证边界

新增严格 HTTP 边界合同测试使用真实卡片、简报和日报构建器，旧实现复现四项
失败，修复后通过；测试不联网、不发送消息。另验原始卡片不被修改、错误层级
不外发、正文和表格保留、错误码留存及敏感响应不落盘。

修复保持已有 occurrence/action 记录，不伪造成功、不重置去重键、不自动重发
已经失败或结果不明的报告。三季报规则仍可在下一有效日期触发；已知 600036
事件的次日窗口是 2026-11-01 09:50（北京时间），并非只能等待明年。

原始线上排查与发布门禁收据位于忽略目录 `.tmp/trigger_failure_20261031/`；
最终部署结果以对应生产发布收据、实际进程和构建指纹为准，结构测试不能替代
真实新消息送达验收。
