# 2026-10-21 简报昨收与未开盘误发修复

用户要求简报增加昨收，并修复尚未开盘仍发送的问题；沿用实验功能不上线的范围。

## 原因

原 QQ 实时接口已提供昨收字段 `[4]` 和报价时间字段 `[30]`，但程序没有传递昨收，
并将行情 `date` 一律写成抓取当天。假期或开盘前返回的旧报价因此被标成新行情。
简报只检查北京时间周末和数据日期指纹；首次运行没有指纹时会放行，跨市场旧报价
也可能改变指纹。这不能证明某市场已经开盘。

服务器原代码隔离复现确认：工作日 09:00 和国庆假期 09:50 均会进入 Session 创建；
2026-05-29 的捕获报价被改成抓取日，而且结果缺少昨收。复现没有真实抓取、调仓或发送。

## 修改

- QQ 报价保留真实源日期和带市场时区的 `quote_time`，读取 `prev_close`；无有效
  时间戳不把报价当作新行情。覆盖实际捕获的 A 股、港股、美股时间格式，保留
  原接口的新加坡报价时区兼容。
- 实时数据刷新经 DataFrame、Session 的动态字段传递昨收和报价时间；没有真实
  昨收时显示 `—`，不以现价、零或推测值代替。
- 复用现有 exchange-calendars：定时简报在抓取前检查配置市场的实际常规交易时段，
  包括假期、午休、半日市与美股夏令时。日历不可用时该市场不放行。
- 抓取后和发送前再次校验：至少有一个当前开市市场的报价，且源时间不早于
  本场开盘、不晚于当前时刻。三个通知渠道使用相同的有效标的集合。
- 邮件表格、飞书原生表格及文本表格、Telegram 文本均新增昨收。手动明确
  `force=True` / `BOT_FORCE=1` 的快照入口继续保留。
- 仍抓取生产完整配置池，未以小范围优化或报告代替全池验收。没有改动策略、
  优化器、生产配置或账户。其他已有脏改动和源文件原有换行均保留。
