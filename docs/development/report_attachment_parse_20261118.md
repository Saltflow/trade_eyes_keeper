## 确认的缺口与实现

- 已归档 PDF 原件、固定哈希和 owner/chat 读取已实现，但没有创建正文解析的入口。新增 `report_attachment_parse(data_id)`，仅接受既有 `report_artifact:<run_id>:<sha256>`，身份来自认证会话，不接受文件路径或身份参数。
- 复用现有 ParsedCache/PDF 后端，明确调用后提取本地文字、存入隐藏附件目录的 `.parsed`，再用 `data_read` 分页读取和页码引用。`report_get/data_read` 仍不暗中解析；不建新队列、数据库、公共索引，不联网、OCR、调用模型或重新发送报告。
- 原件路径、软硬链接、固定回执哈希和 owner/chat 在解析前后检查。私有缓存明确拒绝共享解析器的三类历史重定向元数据，避免越过已检查的目录；既有公共解析兼容读取保留。
- 默认 profile 能调用自己的附件解析，无须开启研究权限。损坏/加密 PDF 失败保留既有解析尝试记录，不自动重试；无文字页返回视觉文字缺口，不声称已 OCR。
- 资源边界沿用原件 8 MiB 限制，附件解析新增 200 页、524288 文字字符上限；超过即拒绝，不截断成成功。文字界限为现有 8 MiB 读取预算预留重复文字、JSON 转义和元数据空间；页数是本轮交互工具的本地工作量预算，不是财务规则。返回值暴露这些限制，资源上限回归证明拒绝行为；研究默认解析不变。仍为进程内原生解析，没有硬 CPU 超时隔离。
- 回测旧 bot_command 路径为先前明确保留项，本轮不扩大范围迁移它。SGX、财务字段及 Ke 缓存属于独立的数据可用性问题，不借此运行全量优化器、补造历史资料或覆盖其他任务改动。
