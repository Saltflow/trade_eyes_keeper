# Baostock 访问控制与封禁恢复

适用行情、财报、行业分类及参考池补数入口。访问策略统一读取
`provider_access.baostock`，示例见 `config/config.yaml.example`。

## 规则与本地策略

[官方黑名单页](https://www.baostock.com/blacklist)在 2026-09-22 公布：每日
API 请求不能超过 50,000 次，不能并发连接；自然年首次封禁 6 小时，以后按当年
累计次数乘 6 小时增长。实际释放时间以官网查询结果为准。研究回执保存在
`data/analysis/baostock_blacklist_research_20260922/official_rules_and_status.json`。

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| `state_dir` | `data/provider_state/baostock` | 从项目根解析，共享连接锁、请求计数与熔断状态 |
| `min_request_interval_seconds` | 2 | 每次真实协议请求发送前限速，包括登录、分页和退出 |
| `daily_request_budget` | 40000 | 按北京时间自然日计数，发送前持久化扣减；失败也占预算 |
| `retry_backoff_initial_seconds` | 60 | 网络错误后的初始冷却及单股重试等待 |
| `retry_backoff_max_seconds` | 900 | 连续失败指数退避的上限 |
| `connection_lock_timeout_seconds` | 1200 | 等待其他进程关闭 Baostock 连接的最长时间 |

连接锁覆盖登录前到本地 socket 关闭后；即使其他来源使用多个工作进程，Baostock
也只有一个项目内连接。进程退出或被终止后，操作系统释放锁。SDK 传输包装只在
会话期间生效，退出后恢复；不修改 site-packages。SDK 把网络错误吞为 `None`、
分页错误当作空结果、空包导致接收循环不退出的情况均转换为明确失败，阻止部分
响应被误存为完整成功。

预算覆盖使用同一状态目录的项目进程，不是官网查询到的整个公网 IP 已用量。
同一出口的其他程序仍会占官方额度。不要为不同任务分设状态目录、删除计数文件
或用多台机器/多个入口重复下载；多机器共享出口时应把 Baostock 采集集中到一处。

## 熔断与恢复

收到黑名单错误时写入持久熔断，不再登录、退出或发送下一页。监督器停止调度，
状态为 `source_blocked`，保留已有检查点及待处理列表。每日预算耗尽也暂停到下个
北京时间自然日。临时网络错误进入共享冷却；监督器等待后有限重试，不立即重排
失败标的轰击源站。损坏的状态文件会拒绝访问，不能把它当作零用量。

预计释放时间只作提示，**不会按计时器自行清除黑名单**。查看本地状态不联网：

```powershell
python scripts/check_baostock_access.py --config data/reference_universe/csi1000_20260921/acquisition_config.yaml
```

到官方预计时间后，读取当前出口的官方状态：

```powershell
python scripts/check_baostock_access.py --config data/reference_universe/csi1000_20260921/acquisition_config.yaml --refresh-official
```

该检查以直连 IPv4 读取公网出口和官网查询接口，不使用 HTTP 代理的另一出口来
解锁 Baostock 的直连 TCP；不执行 Baostock SDK 登录，不保存 IP。
只有完整响应明确表明已解除，才清理本地黑名单。请求失败、未知状态、不完整结果
均不放行；官方确认也不会重置当日请求计数。确认 `blocked=false` 后，再执行
[数据采集文档](data_acquisition_20260921.md)中的续跑命令。

## 2026-09-22 修复与已有数据

原任务只有工作进程数上限，没有跨进程连接锁、协议请求限速或每日计数；失败后
立即重试。修复不改变批次的清单、评估日、原价/复权价、公司行动或 PIT 财报合同。

- 官网在 19:22 的回执显示仍处于封禁，预计释放 22:50:11。该状态已写入共享熔断。
- 旧任务当天的协议请求数无法准确恢复，因此迁移日额外保留预算暂停，至少到
  2026-09-23 00:00；不会伪造旧请求计数，也不会到点自动重启。
- 原批次 `20260921_73ef5673cdfe` 仍有 931 个成功检查点和 69 个待补财报标的。
  69 份已有行情全部通过离线复用验证，启动检查发送 0 次数据请求、创建 0 个子进程。
- 4,931 个行情、行动、元数据、财报与单股检查点文件的前后 SHA-256 完全一致。
  验收回执在 `data/analysis/baostock_access_fix_20260922/`。

续跑优先复用匹配原请求区间及批次指纹的行情，并检查文件结构、原价/复权价、
行动、日期和元数据的一致性；新收据附三文件 SHA-256。孤立文件、损坏文件、
不匹配区间或配置不会被当作缓存成功。旧行情中的部分覆盖和未解释公司行动问题
保持原状，下载完成不代表严格回测验收通过。未来季度不再发起无效财报请求。
