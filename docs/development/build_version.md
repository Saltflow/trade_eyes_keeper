# 可核验的运行版本

版本显示由同一个`src/core/build_info.py`提供：软件版本、已审核源码提交和实际部署源码的构建指纹，例如`v1.18.0 · abcdef0 · 构建 12345678`。日报部署栏、简报、PDF、Bot `/help` 和 `service_status.json.build_info` 使用同一来源，模板不写死版本号。

`pyproject.toml`的`[project].version`是软件版本。发布安装完成后，既有CI入口自动调用：

```powershell
python -m src.core.build_info --write --commit <已推送的完整40位发布提交>
```

命名文件覆盖部署也必须执行此登记步骤，不能从生产旧Git HEAD推断版本。登记文件`data/deployment/release.json`不进入Git。它包括部署批次/带时区时间、软件版本、审核提交和实际`main.py`、`pyproject.toml`、`src`源码及模板完整SHA清单与规范化指纹。它不读取配置、凭据、数据库、缓存或测试证据，也不将登记文件本身算进指纹。

宿主在启动装配、报告worker在业务调用前校验一次并固定当前进程版本；重复读取只返回小摘要，不逐心跳扫描源码或塞整张清单。已固定版本不因磁盘上下一批源码/登记文件变化而冒充新进程；切换仍需先排空/停止旧宿主、安装文件、登记，再启动。完整清单校验包括新增/缺失源码，不能只验证登记文件自己列出的子集。

没有登记时显示“未登记发布”，不使用Git HEAD猜测。损坏登记显示“版本信息异常”，源码变化显示“构建与部署记录不符”；身份展示异常不会中断日报或重启宿主。失败部署/回滚必须恢复或移除新登记文件，不留下错误的新版本。

验收覆盖同源码不同批次的指纹一致性、源码和模板增删改、未知/旧/坏登记、路径/链接拒绝、同进程并发只初始化一次、摘要隔离、PDF及HTML占位符消费、worker早期固定、状态/帮助一致和CI显式提交参数。只增加版本元数据，不更改价格、信号、投递策略、调度时点、持仓或任何实验功能。版本模块正常读取不会连接外网。
