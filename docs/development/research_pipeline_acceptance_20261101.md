## 已实现的正式路径

`financial_pipeline.py run`统一官方目录、年报及修订、共享中立解析、固定合同提取、跨年对齐、七问摘要、经济可比组横评和三轮研究。CLI、Python门面和Feishu工具共享同一状态与预算账本；旧分阶段入口保留，历史runner没有成为动态依赖。

独立host运行冻结worker，检测真实退出而不自动恢复。SQLite共享20路，失败、partial和unknown不自动重发；显式resume只开放未发送任务。归属、usage、未知费用、账户观测、在途与维修预留分别记录。完整缓存命中零模型/维修调用，不要求模型凭据。

输入、发现快照和实际请求有哈希绑定。相同PDF在单块、全量、跨线程及跨进程只构建一次中立材料。行情改变只影响最终研究；财务prompt、schema和历史正文没有修改。

## 实际故障与修复时间线

| 观察/故障 | 修复与验收事实 |
|---|---|
| 已持久化的事件被回调再次按错误形状使用 | `observe(record)`只呈现已有事件，避免重记和阻断模型结算 |
| partial对齐缓存挡住显式resume的未发送块 | 保存年度工作清单，只开放未发块；新对齐写新版本，已发摘要不重跑且注明原输入 |
| 同财年多公司年报互相覆盖 | 全文替换及去重键包含issuer；不同公司发表日期不互相影响 |
| 冻结输入/发现快照和context附件缺校验 | 执行、resume、POST前核验；未验证元数据不得进入收费横评 |
| 真实AAPL目录中的非年报日期晚于申报日期 | 年度入口先筛10-K/20-F/40-F及/A，坏年度行局部隔离；通用公告合同未改 |
| 20路并发下SQLite入队写锁超时 | 研究域SQL短事务共用30秒锁策略；入队失败处理已提交/未提交两种情况，暂停且不留孤儿claim；HTTP仍20路并行 |
| 结算SQL失败丢失已捕获usage | 保留原回执、usage及费用，标执行待核，不制造未知消费或重发 |
| 通知网络调用阻塞核心事件 | 持久化通知intent后由独立发送线程处理；不确定投递不重发，关闭最多等待2秒 |
| 父目录缓存扫描漏子批次摘要/历史请求 | 按正式metadata递归识别批次，分阶段登记全部可证明归属的记录 |
| 完整正文可读但阅读页被独占锁住 | 先红后绿验证；正文、usage及交付索引继续保留，HTML失败单独记录 |
| 原年报partial在缓存复用时从coverage消失 | 使用真实历史4单元格夹具复现并修复；首轮及零调用复用轮均保留partial和年度缺口 |
| 摘要分段可能在并行研究或prompt更新后重新划分 | 按年度版本保存共享分段计划及共用定义，已尝试的摘要不创建新的收费分段 |
| SQLite自身失效导致正常告警也无法入库 | 独立落盘紧急intent，验证冻结spec及原会话后一次告警；真实只读SQLite启动故障已演练，不能持久化时只写脱敏stderr |
| 缺年与上市前/尚未到披露期混淆 | 哈希绑定调用方官方证据单列适用性；无证据不推断，已有报告优先；覆盖真实发现入口且0模型调用 |
