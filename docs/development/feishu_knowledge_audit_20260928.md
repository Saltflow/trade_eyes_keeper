# 飞书助手项目知识与问答留档修复

## 实际问题

用户确认私聊已经能回复后，连续询问公告栏筛选与时效，助手未能解释项目行为。
只读恢复同一私聊中的两条来信和本应用两张回复卡片，未读取其他聊天、未发送消息。
原回复只查询可编辑配置和研究目录，空结果被错误地解释为可能无权访问公告业务。
原助手没有项目文档工具，普通问答上下文仅存在内存；SQLite 只保存提案、任务、
去重收据及操作审计，无法从本地记录复盘这两轮回答。

## 改动

- 文档白名单、目录、关键词搜索与按行读取。每轮服务端先检索，再允许模型补查。
  片段包含部署文档的路径、行号、内容哈希，作为工具数据使用，不改变确认权限。
- 根据线上公告抓取、筛选和邮件呈现实际调用链补充独立公告说明，避免用本地尚未
  部署的其他业务代码解释线上行为。配置查询空结果不再被解释为业务配置不存在。
- SQLite 新增会话和事件表，记录输入、模型返回、工具调用、来源、输出、耗时、
  错误及飞书发送结果。默认30天保留，长度/事件数有界，凭证先脱敏。
- 每轮排查编号关联服务日志；失败发送保留生成答案但不进入已送达上下文。
  重启标记未完成会话 interrupted，不重放；成功历史按聊天和发送者隔离恢复，
  清空对话形成恢复边界。旧问答未伪装成新增版本自动留档的数据。
