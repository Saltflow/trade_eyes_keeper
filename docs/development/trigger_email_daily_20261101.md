# 触发日报邮件与公告上下文修复

日期：2026-11-01。

用户发现关闭固定报告后，三季报触发器仍在09:50同时发送简报和日报，邮件没有收到。核对实际执行记录，11月1日命中的是600036在10月31日公告的次日；简报与日报均获飞书成功回执。原实现遇到`_trigger_context`直接关闭邮件，仅向原认证会话发送。另日报有价格告警时会进入精简提醒路径，飞书省略事件内容。

修复使公告触发的daily动作始终发送完整日报，并把实际匹配事件的标题、原发表时点、来源和URL保存在持久上下文中，合并进日报公告区；不依赖另一个近期公告接口再次返回同一条记录。没有源标题或安全链接时不编造公告。

邮件复用现有SMTP、收件人、正文和附件。受信任配置`notification.email.trigger_report_routes`以精确`owner`和`chat_id`授权触发报告联发，默认空列表；模型和动作payload不能赋权或指定新收件人。发送前复核当前授权、规则revision、原认证会话和配置，在SMTP登录后再次检查撤销。飞书继续仅发往原认证会话；各渠道单独显示成功、失败、跳过或未知，不自动重试已可能送达的报告。

生产配置处理范围为当前用户的触发报告邮件授权，以及触发器3仅保留daily动作（仍按公告当天和次日运行）。固定19:00、09:50、14:30报告继续关闭；逆回购提醒和02:00优化器保留。历史简报/日报、失败与未知回执不重放。

单元验证使用明确标注的合成夹具并mock所有外部服务。发布验收还需核对服务器候选测试、源码构建身份、原配置及账户/策略文件保护、新进程心跳和实际调度注册。SMTP握手或单元回执不等于邮箱收件箱验收；新版本不主动发送测试报告。
