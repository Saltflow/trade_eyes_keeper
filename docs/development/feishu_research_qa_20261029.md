# 飞书研究问答修复（2026-10-29，候选未部署）

## 问题与修复范围

线上只读审计确认助手已开启 Pi、thinking/high，配置上限为 16 轮模型请求、48 次工具调用。回复质量问题不能归为未开思考：单股票指标问题会查数据后直接拼模板；其他问题也可能在模型没有检索时直接结束。本机另有自然语言估值问题被旧研究历史读取路由截走。

本轮只改飞书问答的 `service.py` 和 `harness.py`，同步测试、配置样例与文档。没有改实际主配置、账户、提醒、调度任务或生产文件，没有发送飞书测试消息，没有提交、推送或部署。

## 当前候选行为

- 删除股票指标直接模板返回、自然语言估值历史查询短路及相关死代码。本轮股票预查作为模型输入，由模型分析后回复。
- 常见资料、股票、估值、源码问题和相关连续追问进入研究策略，强制选 Pi；普通闲聊保留配置的 native/Pi 选择。明确的持仓读取和操作回执保持原合同，持仓公司的资料分析不走状态模板。
- 研究问答无本轮资料、也没有实际检索却准备回答时，暂扣该结论并要求补检索一次；仍无检索则明确失败。导航目录与旧会话不算实际检索。
- 本轮已有预查资料时可直接由模型分析，不强迫重复查询。工具失败交回模型，可继续换来源，或明确说明实际尝试及缺口；不能伪造已查成功。
- 模型 HTTP 请求继续携带 `thinking: enabled` 与配置的 `reasoning_effort`；新增问答审计记录实际后端、思考配置、检索次数与资料状态。
- 检索工具的运行错误交给模型处理；写入工具的 RuntimeError 保持原中止语义，不包装成可以继续重试的普通检索失败。
- Pi 缺失不降级直答。只读检索与分析无需确认研究提案；配置修改、脚本/回测执行和激活仍遵守原确认合同。
- 解除旧提示中“所有估值问答必须已有 Fundamental Quant 发布记录”的前提，要求事实、推导、情景假设与来源明确区分。本轮没有恢复旧研究执行器，也没有把独立三轮财报报告接到飞书。

研究识别使用服务端问题与会话线索，并非已验证的通用语义分类器。证据检查能拦截无检索直答和无效源码引用，不等于自动核验全部财务数字或保证模型结论正确。实际需要的资料可来自项目源码、索引数据、归档报告或网页搜索；网页摘要仍为未核验材料。
