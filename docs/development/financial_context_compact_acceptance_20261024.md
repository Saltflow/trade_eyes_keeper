完整模型输入为该目录的`模型输入.md`；每家公司另有完整`模型正文.md`，HTML仅提供同一正文的阅读排版。JSON为保留映射和验收证据，不作为默认模型输入。

## 本轮改动

只改第二阶段的 `src/fundamental_data/model_context.py` 和 `scripts/build_financial_context.py`，新增独立保留测试；未增加运行模块或第三方依赖，未加入统计模型。

- 共同口径C、原缺失说明M、重复说明N和原科目路径前缀G，按原文完全相同进行共用；每份公司正文均包含自己的完整定义。定义自身也去掉重复。
- 只有已明确对齐的列，且期间、角色、调整状态及其他列口径完全相同，才共用展示期间列。调整状态未说明时继续分列。
- 同口径且值、缺失原因及单元格例外都相同的观测共显，保留所有来源映射；不同值或不同缺失说明逐披露版本并列，未选择某一版覆盖其他版。
- 明确期间按实际日期排序；未知或歧义原表保留原列顺序。按每行实际覆盖列分组，不填出新的空白交叉矩阵。
- 独立行的解释集中说明，行内保留来源标记。路径前缀只复用文字，不用于推断行身份或跨年匹配。
- 修正数值列context及按原列键保存的cell_context在正文中的展示；无数值行的说明、未使用原列、未对应值的缺失/期间/例外字段继续显示。
- 保留原有表/行身份匹配规则，未加入同义词推测、单位换算、缺失填补、JSON补修或额外财务门槛。
- 验收失败时保留已生成的各家公司正文和完整报告，最后返回失败状态；不会因一家公司验收失败而停止保存其他公司。

## 复现

输出目录必须全新，运行时不触发提取API：

```powershell
python -B -X utf8 scripts/build_financial_context.py --source-run data/fundamental_data/three_companies_fixed4_20261024_115306 --baseline data/fundamental_data/stage2_model_context_20261024_125223_final --output data/fundamental_data/<new-output>
```
