## 公告栏会筛选哪些

日报入口读取 `announcements`（复数）配置；只有 `announcements.enable` 开启才采集，输入是 `config["stocks"]` 中的监控标的。配置入口不能写成单数 `announcement`。部署代码依据：`main.py:1360`、`main.py:1368`。

采集和筛选分为三步：

1. **标的范围**：按股票代码前缀识别沪深市场；以 `51`、`52`、`15`、`16`、`18` 开头的基金代码直接跳过。没有独立的港股、美股或基金公告采集通道，不能据此声称覆盖全部市场。依据：`src/data/announcement_fetcher.py:115`。
2. **日期窗口**：普通公告使用 `announcements.days`；标题含“分红、利润分配、派息、送股、转增”的公告使用较长的 `announcements.dividend_days`。无法解析日期的记录会被跳过，窗口按公告日期和抓取当天的日历日期比较。依据：`src/data/announcement_fetcher.py:152`。
3. **标题关键词与数量**：有重要关键词命中的公告时，每只股票只取来源顺序中的前 **5 条重要公告**；该股完全没有重要公告时，才取前 **3 条其他公告**。不是所有公告都输出，也不是用模型阅读全文后给重要性评分。依据：`src/data/announcement_fetcher.py:573`、`src/data/announcement_fetcher.py:633`。

重要关键词包括以下类别，实际匹配方式是标题包含关键词：

| 类别 | 标题关键词 |
| --- | --- |
| 业绩与定期报告 | 业绩预告、业绩快报、业绩变动、业绩修正、年报、半年报、季报 |
| 分红送转 | 分红、利润分配、派息、转增、送股 |
| 经营与资本运作 | 重大合同、重大投资、资产重组、并购、减持、增持、回购、股权激励 |
| 风险与监管 | 风险提示、澄清公告、问询函、关注函、监管函、立案调查、诉讼、退市、ST、*ST |
| 融资 | 担保、贷款、债券、可转债、非公开发行、定向增发、配股 |

关键词不涵盖所有同义说法，源列表在截取前也没有显式重新排序或重要性评分；因此“重要”是这套标题匹配规则的结果，不代表完整的重大事项判定。完整关键词依据：`src/data/announcement_fetcher.py:592`。

## 邮件摘要还会再筛一次吗

当前部署的日报邮件由 `_build_daily_events_section` 生成“事件速览”。公告部分接收前述已经筛选的结果，按日期和代码倒序排列；它与待处理分红、未解禁定增一起展示。排序先是“已除权未派息”，再是“未除权”，之后是定增和公告。邮件这一层使用 `selected = events`，不会再次设置总条数上限或只显示有交易信号的股票。依据：`src/notification/email_notifier.py:1397`、`:1433`、`:1481`、`:1500`。

所以“邮件把收到的公告都展示出来”和“抓取时完全不筛选”是两回事：邮件保留上游结果，但上游已执行日期、标题和每股条数筛选。分红事项的状态筛选也是另一条事件逻辑，不能等同于公告标题筛选。

当前主链是 `main.py` 采集公告 → `session.announcements` → 日报邮件 `_build_mobile_daily_email_body` → `_build_daily_events_section`。依据：`main.py:1372`、`src/notification/email_notifier.py:1622`、`:1657`。文件中另有旧公告展示函数，不能拿它们的展示条数替代当前日报链路规则。

## 时效性：多久更新、能看到多早的公告

日报是在任务执行时抓取公告，再随报告发出；没有持续监听交易所新增公告的通道。调度器的日报默认在 **Asia/Shanghai 19:00** 触发，实际时间应以当前调度配置为准。这个时间是任务启动时间，采集、计算和生成报告需要时间，所以不代表 19:00 已送达，更不代表公告发布后立即推送。依据：`src/core/schedule_manager.py:57`、`:85` 和 `main.py:1359`。

日报入口的普通公告默认窗口为 **7 天**，分红相关标题默认窗口为 **420 天**。长窗口是为了保留分红方案等信息，并不表示这些旧公告刚刚发布，也不表示已派息与待派息的状态相同。直接调用 `get_recent_important_announcements` 的函数默认 `days=3`；日报入口会明确传入 `announcements.days`，不能把这个函数默认值误说成日报当前只看 3 天。依据：`main.py:1366`、`:1367`、`src/data/announcement_fetcher.py:573`。

窗口比较使用公告的日历日期；目前解析和筛选以部署主机日期为基准，没有分钟级“新鲜度”或严格的最大推送延迟保证。时效还受上游网页更新、网络、正文获取和任务耗时影响。当天采集之后才出现的公告，通常要到下一次日报运行时才有机会出现。

2026-09-28 只读核对的部署配置快照：公告已开启，普通窗口 **7 天**，分红窗口 **420 天**，日报调度 **19:00 / Asia/Shanghai**。这是核对时的快照，不保证以后仍相同；回答“现在的值”应查询实时配置，查询工具未覆盖这些字段时必须说明限制，不能把查询为空解释成配置不存在。

## 数据来源和已知覆盖限制

当前抓取器的有效来源是新浪财经个股公告网页；名称中虽保留沪深交易所方法，上交所、深交所旧主接口已经返回空列表，实际走新浪页面。每次只请求当前公告列表页，没有向后翻页补齐整个时间窗口。因此 **420 天是过滤窗口，不是“过去 420 天公告全部抓全”的承诺**。依据：`src/data/announcement_fetcher.py:322`、`:382`、`:450`、`:480`。

网页请求失败、页面结构变化、日期解析失败、代码不在支持范围、关键词未覆盖或数量截取，都可能造成遗漏。当前部分失败会记录日志并返回空列表；“暂无公告”不能单独证明这只股票没有发布公告。依据：`src/data/announcement_fetcher.py:113`、`:146`、`:186`、`:401`、`:469`。

启用正文抓取与 LLM 提取后，程序只对标题命中的分红类公告尝试补充分红细节；这不是所有公告的语义筛选或全量摘要。正文/模型失败时一般保留原公告，不应把缺少提取结果说成没有分红公告。依据：`src/data/announcement_fetcher.py:214`、`:224`、`:256`、`:286`。

## 在飞书修改公告参数

公告七项业务字段现在支持自然语言生成预览，再发送 `确认 <编号>` 保存：
`announcements.enable`、`days`、`dividend_days`、`enable_content_fetching`、
`enable_llm_extraction`、`max_llm_calls_per_run`、`max_pdf_size_mb`。
字段能力以 `read_configuration` 本次查询的 `writable` 为准，不沿用旧会话中的
“公告只读”结论；不需要登录主机。未给新值时先说明可编辑范围，不自行更改配置。
确认后在下次任务读取新值，已开始任务仍使用原快照；凭证及部署权限不在开放字段中。
其中 `days`/`dividend_days` 是抓取结果的回看筛选窗口，不是公告档案保存期限。
`max_llm_calls_per_run` 的当前实现按单次公告丰富调用累计成功提取数，非全报告
所有请求（含失败/重试）的全局上限。
