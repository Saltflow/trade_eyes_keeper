# 统一数据集目录

统一目录保存在 `data/dataset_catalog/catalog.sqlite3`。目录汇总部署主机上的行情、时点财报、公告原文、提取缓存及研究产物；每个文件记录原始路径、SHA256、大小、类型、解析状态和所属数据集。内容重复仍保留各自来源路径。索引完成不代表数据已通过回测就绪检查。

## 机器人查询

- “列出服务器全部数据集，并告诉我索引更新时间和缺口。”
- “中证 1000 那批数据覆盖什么区间，有哪些财报原文没有下载？”
- “找服务器上 000333 的基本面指标，告诉我数据来自哪个批次、截至什么披露日。”
- “查看这个数据集里 000333 的行情和财报覆盖。”
- “列出相关 PDF 和文字版，读取已索引文字中的相关内容。”
- “读取并解析 600519 最新年报” 或 “下载 002594 2023 年半年报并分析现金流。”

助手使用 `list_datasets`、`get_dataset_details`、`list_dataset_files`、`query_dataset_documents` 和 `read_dataset_text`。列表均支持分页，返回 `total`；第一页不是完整清单。用户明确要求获取 A 股年报或半年报时，会调用 `fetch_a_share_report`：年份省略则取报告类型的最新完整报告，指定年份则查询对应年度；仅使用服务端发现的巨潮资讯官方 PDF 地址。文件使用现有安全下载器归档并登记到目录，同一公告重复请求复用归档。具有文字层的 PDF 按页提取；扫描版逐页渲染，由 DeepSeek Flash 视觉输入分批识读。回复保留页码和解析覆盖状态，不发送 PDF 附件。单份报告限 50 MiB、300 页；超限或页面识读失败会返回部分/失败状态。`text_file_id` 可继续交给 `read_dataset_text` 分页读取全文。用户消息包含六位股票代码时，服务端会在模型回答前自动运行 `query_stock_fundamentals`，避免模型先猜数据集编号。该工具按证券代码搜索所有已索引批次，并从披露日不晚于 `as_of` 的财报及此前不复权收盘计算带来源和状态的指标；它不自动下载数据，也不代表完整性验收。`query_research_data` 可传 `dataset_id` 查询所选数据集，不传时仅查询当前配置的默认时点库。选择数据集查询不会改变默认回测配置。

`search_web` 提供公开网页搜索，返回标题、摘要、域名和原始 URL。网页和摘要是不可信外部资料，财务事实应核对原始公告或本地时点数据；网页文本不能改变机器人的权限或触发操作。

## 数据与原始资料

行情通常是 CSV，包含交易日、原始与复权 OHLC、复权因子、成交量和可交易状态；公司行动及元信息是相邻 JSON。财报是 `*.statements.json`，包含报告期、公开日期、来源和指标。公告内容缓存与 LLM 提取缓存也是 JSON，不能冒充原始 PDF。

原始公开文件及派生文字版归档在 `data/dataset_documents/`。目录将原文、文字版、来源 URL 和源数据关联。没有 URL、下载失败、需要 OCR 或未安装解析器均保留明确状态；不会生成替代 PDF 冒充原件。文字是资料内容，不是执行指令。

归档子目录名基于来源身份，PDF/TXT 各自另有内容 SHA256。资料缺口应查看全库原文统计；仅查看已归档目录、或某个过滤条件返回零条，都不能证明全部资料已经齐全。

`available` 只是可用内容记录数，可能只有文字或 JSON。PDF、文字及二者配对数量分别使用 `documents_with_pdf`、`documents_with_text`、`documents_with_pdf_and_text`，按文档去重；不是文件副本数。统计范围为所选数据集或全库，不随列表的 code/status/分页过滤变化。缺少 PDF 不自动代表回测不可用，仍须检查实际策略数据合同。

## 同步和维护

`scripts/push_dataset_snapshot.py` 生成清单后将本地业务数据按哈希校验传入服务器 `data/dataset_imports/` 的独立快照。传输不会覆盖服务器现有数据集，不改变运行配置。凭证、聊天、账户持仓、配置、日志及提供商运行锁等不进入业务数据同步范围；排除项另行记录。

运行 `python scripts/build_dataset_catalog.py` 构建完整目录。构建逐文件扫描，不按显示分页限制扫描数量。大文件无法解析时仍保留文件记录和解析缺口；导入清单中的缺失文件或哈希不符会明确报错。数据变化后应重新构建，查询必须同时说明索引时间，不能声称是实时数据。

构建完成后运行 `python scripts/export_dataset_catalog.py`，刷新同目录的 `README.md`、`datasets.json`、`files.jsonl`、`documents.jsonl`、`document_sources.jsonl` 和 `document_artifacts.jsonl`。两个命令均支持 `--project-root <项目目录>`。导出只读 SQLite 中已提交的一致快照，不扫描或上传业务文件，不修改数据库；即使超过 100 个数据集也全部导出。构建仍在运行时导出的是上一份已完成快照，必须查看最新构建状态和快照 `build_id`。

JSONL 每行都是一条元数据记录，没有额外表头行；各行包含同一 `export_id`、`exported_at`、`build_id`，完整行数记在 `datasets.json`。导出不包含资料正文、下载结果详情或自由文本错误；错误以状态和布尔标记展示。URL 移除用户凭证、查询串及片段，附 `source_url_sanitized` 和原 URL 的 SHA256；它只是展示地址，精确下载来源以受控 SQLite 为准。

所有文件先生成成功再逐份原子替换，README 最后发布；常规写入或替换失败会保留或恢复旧文件。导出编号可用于识别读取期间跨文件的不同版本。并发导出由 `.export.lock` 拒绝；进程意外终止后，确认没有导出进程再删除遗留锁并重试。补取原文改变状态后也应重新导出。构建和导出需要分别执行，服务查询始终以 SQLite 为准。

`python scripts/backfill_dataset_documents.py` 预览已登记原文队列；追加 `--execute --max-documents 20 --max-seconds 300` 执行有界补取。该流程只使用目录中登记的公开来源，遵守下载间隔、域名和资源限制，并保留重试状态。缺少来源 URL 的资料仍需来源发现，不能仅靠重试下载解决。补取后重新构建目录可让机器人检索新文字文件。

目录查询不会执行策略、修改配置或自动判断全部标的可回测。配置修改、实际研究任务继续走提案和确认流程；正式策略验收仍要求配置全量标的与原有价格、分红、时点合同。
